# Классификатор «духи / нет» и тип кадра (задача #38)

Эксперимент: SigLIP 2 (zero-shot, затем линейный слой на замороженных эмбеддингах)
против бейзлайна EfficientNet-B0 (полное дообучение).

## Данные

Датасет размечен вручную (`dataset.jsonl`, `meta.json`, папка `orig/` с фото, лежит на Google Drive команды).

- 7150 записей `barcode + uri` -> 5510 уникальных фото (один uri может относиться к нескольким баркодам).
  Модель обучается на уникальных фото.
- На Drive в `orig/` лежит 5500 файлов, 10 фото из `dataset.jsonl` там отсутствуют. Они пропускаются с предупреждением.
- Тип кадра (`studio` / `casual` / `graphic` / `document`) – одно значение на фото.
- **Негативных примеров в датасете нет**: `is_negative = false` во всех 7150 записях.

Сплит train / val / test = 4407 / 552 / 551 фото (~80/10/10), стратифицирован по типу кадра.
Группировка идёт по связным компонентам графа «фото – баркод», поэтому один товар (и общие фото)
не попадает в разные части (проверено: ни один баркод не лежит в двух частях).
После пропуска отсутствующих фото в тесте 550 снимков.

## Результаты (тип кадра, test, 550 фото)

| Модель | accuracy | macro-F1 |
|---|---|---|
| SigLIP 2 base (224), zero-shot | 0.722 | 0.592 |
| SigLIP 2 base (224) + линейный слой (LogReg, C=30) | 0.929 | 0.935 |
| EfficientNet-B0, полное дообучение (6 эпох) | **0.946** | **0.947** |

F1 по классам (zero-shot / linear probe / EfficientNet-B0):

| Класс | zero-shot | linear probe | EfficientNet-B0 |
|---|---|---|---|
| studio | 0.791 | 0.934 | 0.960 |
| casual | 0.389 | 0.873 | 0.890 |
| graphic | 0.887 | 0.950 | 0.947 |
| document | 0.300 | 0.981 | 0.991 |

Выводы:

- Zero-shot для типа кадра слабый: модель почти всё относит к `studio` (recall 0.96, но `casual` 0.25 и `document` 0.23).
  Критерии разметки («фото в быту», «скан листа») плохо выражаются короткими промптами.
- Линейный слой поверх замороженного SigLIP 2 даёт +34 п.п. macro-F1 к zero-shot, при этом обучение занимает секунды
  (эмбеддинги считаются один раз, ~5 мин на CPU).
- EfficientNet-B0 с полным дообучением оказался чуть лучше линейного слоя SigLIP 2 (на 1.6 п.п. accuracy, ~9 фото из 550).
  На тесте такого размера разница находится на границе статистической значимости, поэтому уверенного вывода о победителе нет.
  Основная доля ошибок обеих моделей – путаница `studio` <-> `casual`.
- Стоимость: EfficientNet-B0 учился ~26 мин на 4 ядрах CPU, SigLIP 2 base – ~5 мин на эмбеддинги + секунды на голову.
  SigLIP 2 удобнее, если нужно быстро менять задачи/классы поверх одних и тех же эмбеддингов.

Ограничения: один сплит и одно зерно, без кросс-валидации и без подбора гиперпараметров EfficientNet-B0 (lr, число эпох).
SigLIP 2 base-224 – самый лёгкий вариант, более крупные чекпоинты (`so400m`, 384) на CPU не проверялись.

## «Духи / нет»

В размеченном датасете только позитивы (`is_negative = false` во всех записях), поэтому негативы собраны из внешних источников.

### Данные

| Набор | Что это | Размер |
|---|---|---|
| Позитивы | фото духов из датасета команды | 5500 |
| Негативы (ABO) | [Amazon Berkeley Objects](https://amazon-berkeley-objects.s3.amazonaws.com/index.html), CC BY 4.0: фото товаров маркетплейса. 1000 «уход / косметика» (`hard`) + 1870 остальных товаров (`easy`, не более 40 на тип товара) | 2870 |
| Внешний тест (Myntra) | [Fashion Product Images](https://www.kaggle.com/datasets/paramaggarwal/fashion-product-images-dataset) (зеркало `Marqo/KAGL`): духи и подарочные наборы против случайных не-духов того же магазина | 214 + 600 |

Из ABO удалены все листинги, где в любом поле на любом языке встречается что-то про аромат (perfume, parfum, cologne, eau de, fragrance, deodorant и т.д.),
чтобы в негативы не попали настоящие духи. Корзину `hard` стоит читать осторожно: это в основном уход, витамины, бытовая химия и батарейки, а не флаконы, похожие на духи.
Парфюмерии в ABO по сути нет (совпадения по словам – «Fragrance Free» и чехлы для телефонов с принтом флаконов).

Сплит основного набора: train 4400+2296, val 550+287, test 550+287 (позитивы + негативы).
Все изображения проходят одну и ту же нормализацию (ограничение размера 256 px и повторное JPEG-сжатие 90),
чтобы источник нельзя было угадать по разрешению. Zero-shot негативов не видит, остальные модели учились на них.

### Главная оговорка: артефакт источника

Позитивы и негативы из разных источников, поэтому классы отличаются фотостилем, а не только содержимым. Проверка: градиентный бустинг
на восьми простых статистиках пикселей (яркость, доля белого, резкость, размер JPEG) без всякого понимания содержимого даёт на тесте
**ROC-AUC 0.94** (0.93 даже если брать только студийные фото духов). Поэтому результаты обученных моделей на основном тесте – оценка сверху.
Для этого добавлен внешний тест из одного источника (Myntra): там духи и не-духи сняты в одном стиле, и угадать класс по источнику нельзя.

### Результаты на основном тесте (550 духов + 287 негативов)

Порог для обученных моделей и для «zero-shot (порог по val)» подобран по F1 на val; «без подбора» – правило «духи выигрывают у не-духов».

| Модель | ROC-AUC | recall духов | precision духов | FPR (простые) | FPR (уход/косметика) |
|---|---|---|---|---|---|
| SigLIP 2 zero-shot, без подбора | 0.993 | 0.996 | 0.864 | 0.119 | 0.677 |
| SigLIP 2 zero-shot, порог по val | 0.993 | 0.967 | 0.980 | 0.005 | 0.108 |
| SigLIP 2 zero-shot, промпты v2* | 0.999 | 0.993 | 0.978 | 0.026 | 0.075 |
| SigLIP 2 + линейный слой | **1.000** | 1.000 | 0.996 | 0.000 | 0.022 |
| EfficientNet-B0 | 0.999 | 0.989 | 0.995 | 0.015 | 0.000 |

\* Промпты v2 дописаны после просмотра негативов (косметика, витамины, бытовая химия) и подобраны на val, поэтому цифры оптимистичны.
Базовые промпты (v1) написаны до сборки негативов.

Recall по типу кадра у обученных моделей ≥ 0.94 везде; единственный заметный провал – `document` у EfficientNet-B0 (0.943, 53 фото в тесте).
Тест небольшой: 287 негативов (из них около 100 в корзине `hard`), одна ошибка – это 0.3 п.п. FPR.

### Внешний тест из одного источника (214 духов + 600 не-духов Myntra)

Пороги те же, что выбраны на основном val, без подстройки под Myntra.

| Модель | ROC-AUC | recall духов | FPR | accuracy |
|---|---|---|---|---|
| SigLIP 2 zero-shot, без подбора | 1.000 | 1.000 | 0.015 | 0.989 |
| SigLIP 2 zero-shot, порог по val | 1.000 | 1.000 | 0.000 | 1.000 |
| SigLIP 2 + линейный слой | 1.000 | 1.000 | **0.112** | 0.918 |
| EfficientNet-B0 | **0.953** | 0.949 | **0.272** | 0.786 |

- SigLIP 2 ранжирует идеально и без обучения, и с линейным слоем. У линейного слоя порог «уехал» (FPR 11% при пороге с основного val),
  то есть для боевых данных порог нужно калибровать на фото из целевого домена.
- EfficientNet-B0 на данных нового источника заметно деградирует (AUC 1.00 -> 0.95, FPR 27%): он частично выучил отличия стиля фото
  ABO и датасета духов. Для него в проде нужны негативы из того же источника, что и боевые данные.
- Негативы Myntra – одежда и аксессуары, косметики там почти нет (в скачанных шардах), так что это проверка устойчивости к источнику,
  а не к «сложным» негативам. Сложные негативы (флаконы косметики, похожие на духи) в этой работе проверены только на ABO.

### Выводы

- Лучший кандидат: **SigLIP 2 + линейный слой**. Идеальное ранжирование в обеих проверках (в отличие от EfficientNet-B0, не деградирует на другом источнике), обучается за секунды. Порог нужно калибровать на реальных данных маркетплейса.
- Zero-shot SigLIP 2 без обучения даёт AUC 0.993 и годится как быстрый фильтр, но чувствителен к порогу и формулировкам промптов
  (FPR на косметике от 0.68 до 0.08 в зависимости от них).
- Окончательный выбор и порог надо подтверждать на реальных ошибочных загрузках с маркетплейса: оба набора негативов – публичные,
  и реальное распределение «не духов» в заявках на маркетплейс может заметно отличаться.

## Как воспроизвести

```bash
cd model/training/frame_classifier
pip install torch torchvision transformers pillow scikit-learn numpy   # CPU-версия torch достаточна

# DATASET – папка с dataset.jsonl и orig/, WORK – куда писать кэш и результаты (вне репозитория)
python siglip_experiment.py --dataset-dir DATASET --work-dir WORK        # zero-shot + linear probe
python efficientnet_baseline.py --dataset-dir DATASET --work-dir WORK    # бейзлайн, ~25 мин на CPU
```

Бинарная задача (духи / нет), нужны архивы ABO и несколько parquet-шардов Myntra (ссылки в докстрингах скриптов):

```bash
python build_negatives.py --abo-dir ABO --out-dir NEGATIVES            # в ABO лежат listings.tar и images-small.tar (переименованные abo-listings.tar, abo-images-small.tar)
python build_external_eval.py --shards KAGL/data-*.parquet --out-dir EXTERNAL
python perfume_detection.py --dataset-dir DATASET --negatives-dir NEGATIVES --work-dir WORK   # ~1 ч на CPU
python evaluate_external.py --external-dir EXTERNAL --work-dir WORK
```

Метрики прогона из этого отчёта лежат в `results/`. Веса и кэш изображений не коммитятся
(`*.pth`, `*.npy` в `.gitignore`).

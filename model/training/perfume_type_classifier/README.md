# Классификатор типа парфюмерии

Задача: дополнить проверку R3 `perfumery_type`, когда в наименовании нет явного типа.
Обучение находится здесь, запуск готовой модели - в
`algorithms/src/carat_algorithms/text/perfumery_type/model.py`.
Отдельный сервис и изменения API не нужны.

## Данные

Команда проекта передаёт файлы заказчика:

- `ТГ Парфюмерия - Категория Духи (все атрибуты) (1).xlsx`;
- `perfumery_brands.csv` с полями `barcode`, `text`.

Передайте каталог через `--data-dir`. Данные и веса не добавляйте в Git.
Публичной ссылки и сведений о лицензии нет; уточните условия передачи у команды.

`train_catalog.py` использует заявленные типы из Excel и слабые метки из CSV.
Слабые метки определяются текущими правилами `algorithms`, без старого нечёткого
словаря прототипа. Названия с упоминанием набора, аналога или оригинала исключаются
из слабой разметки. Это новый запуск эксперимента, старые метрики к нему не относятся.

## Обучение и экспорт

Из этого каталога:

```powershell
uv sync --locked
uv run python -m unittest test_export -v
uv run python train_catalog.py --data-dir 'D:\путь\к\данным' --artifacts-dir '..\..\artifacts'
```

Параметры повторяют архитектуру прототипа: word TF-IDF, униграммы и биграммы,
`min_df=2`, `max_features=300000`, sublinear TF, L2-нормализация;
`SGDClassifier(loss="log_loss", alpha=2e-6, class_weight="balanced", max_iter=30)`.
Seed 42. Многоклассовый sigmoid one-vs-rest с нормализацией суммы ответов.

Экспорт сохраняет словарь, IDF, коэффициенты и смещения в JSON без исполняемых
объектов. Runtime использует стандартную библиотеку Python, поэтому новые ML-зависимости
в `algorithms` не нужны. Формат поддерживает от трёх классов.
Проверка экспорта сравнивает ответы с scikit-learn (`rtol=1e-5`, `atol=1e-6`).
Для названия без известных признаков runtime воздерживается от ответа.

Выходные файлы в `model/artifacts/perfume_type_classifier/`:

- `model.json` - обученная модель;
- `model.json.sha256` - контрольная сумма;
- `training_report.json` - выборка, seed, измерения, метрики и ограничения.

Скопируйте `model.json` в `weights/perfume_type_classifier/model.json`.
Бэкенд передаёт корневой `weights/` через существующую настройку `WEIGHTS_DIR`.
Перезапустите процесс после замены весов: модель загружается лениво один раз под блокировкой.
Передайте файл команде через согласованное хранилище; обычный PR содержит только код,
документацию, lock-файл и небольшой отчёт. Источник артефакта - этот скрипт и локальные данные заказчика.

## Результаты и ограничения

`results/training_report.json` содержит результаты локального запуска.

| Измерение | Локальный запуск 2026-11-04 |
|---|---|
| Обучающая выборка | 233191 названий |
| Тестовая выборка | 26650 карточек |
| Accuracy относительно заявленного типа | 0.997261 |
| Macro F1 относительно заявленного типа | 0.615072 |
| Обучение классификатора с TF-IDF на CPU | 14.65 с, без подготовки данных |
| Размер JSON | 21555034 байта |
| 1000 последовательных runtime-вызовов на CPU | 0.080 с, без холодной загрузки |

scikit-learn сообщил `ConvergenceWarning`: достигнут лимит `max_iter=30`.
Этот запуск сохранён как базовый; подбор параметров и проверка редких классов остаются
следующим экспериментом. Низкий macro F1 нельзя скрывать высокой общей accuracy.

Разбиение: GroupShuffleSplit по нормализованному наименованию, 30% в тесте, seed 42.
CSV-записи с тестовыми наименованиями или кодами исключены. Для каждого класса
из оставшегося CSV берётся не более 60000 строк. Повторы обучающих названий и
названия с противоречивыми метками удаляются.

Accuracy и macro F1 сравнивают предсказанный тип с заявленным типом, который может
быть ошибочным. Они не измеряют precision/recall обнаружения нарушений.
Для оценки новой проверки нужна экспертная
разметка, особенно названий без явного типа.

## Поведение проверки версии 2

Существующие правила имеют приоритет. Только `PERFUMERY_TYPE_NOT_FOUND` запускает модель.
Наборы, пропуски, пустые строки и неоднозначные правила не обходятся через модель.
Если заявленный класс не поддерживается, возвращается `REVIEW`.

| Условие | Результат |
|---|---|
| Нет файла весов | `NOT_CHECKED / PERFUMERY_MODEL_WEIGHTS_MISSING` |
| Другой класс имеет оценку >= 0.9, заявленный < 0.1 | `WARNING / PERFUMERY_MODEL_MISMATCH` |
| Модель дала ответ без достаточного основания для предупреждения | `REVIEW / PERFUMERY_MODEL_REVIEW` |
| Нет известных признаков или заявленного класса в модели | `REVIEW / PERFUMERY_MODEL_NO_EVIDENCE` |
| Файл установлен, но повреждён | Бэкенд регистрирует `ERROR / CHECK_CRASHED` |

Оценки модели не калиброваны; пользователю они не показываются как проценты.
Совпадение по модели не становится `PASS`: явного обозначения типа всё ещё нет.
Порог 0.1 взят из прототипа и требует проверки на экспертной разметке для этого сценария.

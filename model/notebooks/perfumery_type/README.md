# Perfumery Type Name Check Research (R3)

**Location:** `model/notebooks/perfumery_type/`
**Scope:** Rule-based evaluation of the `perfumery_type` name check (requirement R3).

## Contents

- `research.ipynb` — research notebook for loading the labeled sample, comparing two baseline rules with R3, calculating metrics, plotting results, and reviewing mismatches.

## Goal

Evaluate how the rule-based check compares the perfumery type detected in a product name with the value declared in the product-card attribute, and compare it with two simplified baselines.

The notebook imports the existing implementation from:

- `algorithms/src/carat_algorithms/text/perfumery_type/`;
- `model/perfumery_type/evaluation.py`;
- `model/perfumery_type/perfumery_name_check.py`.

**Evaluation boundary:** the notebook evaluates the rule-based `check_perfumery_name()` function. It does not evaluate the ML fallback inside `PerfumeryTypeCheck`, load model weights, or run other Carat checks.

## Data source

The notebook requires an approved `gold_labeled.csv` file with the following columns:

- `name`;
- `declared_type`;
- `expected_status`.

The dataset is external and is not included in the repository. According to `model/perfumery_type/README.md`, obtain the approved labeled sample from the task owners. There is no public download URL documented for this dataset; request access from the owners of Taiga task [#29](https://taiga.nikdor.xyz/project/cogniflex/t/29).

Do not add the CSV or any other dataset to the pull request.

Set the path before launching Jupyter.

PowerShell:

```powershell

```

```bash
export PERFUMERY_GOLD_CSV=/path/to/gold_labeled.csv
```

## Results on the currently supplied sample

The current local sample contains 15,000 rows. The metrics below are reproduced by the notebook and cross-checked against `model/perfumery_type/evaluation.py`.

| Method | Accuracy | Macro-F1 | Mismatches |
|---|---:|---:|---:|
| Naive first-marker comparison | 98.90% | 72.36% | 165 |
| Conservative rule | 96.71% | 70.72% | 494 |
| R3 rule-based | **99.95%** | **96.25%** | **7** |

All seven R3 mismatches involve the `КОМПЛЕКТ` attribute: the implementation returns `not_checked`, while the supplied labels contain `ok` for six rows and `manual_review` for one row.

## Limitations

- The target implementation description states that some labels in the full 15,000-row sample may have been generated by the algorithm itself. The metrics therefore measure agreement with the supplied labels, not independent real-world accuracy.
- The `manual_review` class contains only four rows, so conclusions about this class are limited.
- The baseline methods use the same parser and type dictionary as R3. This is a comparison of simplified decision rules, not independent systems.
- The ML fallback inside `PerfumeryTypeCheck` is not evaluated. That would require an agreed evaluation protocol, available model weights, and an independent labeled sample.
- The expected handling of product bundles should be aligned with the owners of the requirements and reference labels.

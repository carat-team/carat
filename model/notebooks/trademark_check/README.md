# Проверка соответствия товарного знака наименованию товара

**Задача #28.** Проверяется критерий «Значение атрибута „Товарный знак“ не соответствует наименованию товара» для записей о парфюмерной продукции.

Здесь находятся **исследовательские Jupyter Notebook**, а не готовый модуль backend / `inference/`. Реализацию для интеграции с бэкендом команда планирует вынести в **отдельный Pull Request** после согласования контракта и архитектуры (включая требуемый Java-модуль).

## Состав каталога

| Файл | Назначение | Когда открывать |
|---|---|---|
| `research_ru.ipynb` | Подробный русскоязычный разбор построения правил, справочников, проверок и оценки | Чтобы разобраться в методологии и ходе разработки |
| `algorithm_reference.ipynb` | Краткая техническая версия алгоритмического baseline | Чтобы быстро изучить реализацию и контрольные тесты |
| `algorithm_explained_ru.ipynb` | Та же базовая логика, но с русским словарём терминов, комментариями и подписями | Для обучения, документации и обсуждения с командой |
| `full_dataset_analysis_ru.ipynb` | **Рекомендуемый основной ноутбук**: ускоренная обработка всего датасета, статистика и экспорт CSV | Для полного анализа данных |

> `algorithm_reference.ipynb`, `algorithm_explained_ru.ipynb` и часть `research_ru.ipynb` воспроизводят общую логику baseline, но служат разным целям. Они не являются независимыми ML-моделями. Для полного запуска используйте **`full_dataset_analysis_ru.ipynb`**.

## Входные данные

Нужен **`perfumery_brands.csv`**, который **не входит в репозиторий**. Источник/доступ к CSV необходимо запросить у владельца данных или тимлида; не размещайте его в PR.

Обязательные столбцы:

- `brand` — заявленное значение атрибута «Товарный знак»;
- `text` — наименование товара;
- `brand_in_text` — исторический вспомогательный признак, используемый при построении справочников.

В боевом вызове `check_trademark(brand, text)` используются только `brand` и `text`, но при подготовке статистических справочников необходима историческая выборка.

**Как указать путь к данным:**

- положить `perfumery_brands.csv` в текущую рабочую папку Jupyter или один из трёх уровней выше;
- либо задать переменную окружения `PERFUMERY_BRANDS_PATH` с полным путём к CSV.

Например, в **PowerShell** перед запуском Jupyter:

```powershell
$env:PERFUMERY_BRANDS_PATH = "C:\data\perfumery_brands.csv"
```

Проверьте, что выбран правильный Python kernel, и запустите ячейки сверху вниз (**Run All**).

## Как работает алгоритм

1. Нормализует текст и смешение латинских/кириллических символов.
2. Проверяет заполненность и качество входных атрибутов.
3. Обрабатывает значения типа «Без товарного знака», «Нет» и др.
4. Проверяет точное совпадение и алиасы брендов.
5. Ищет проверенные связи «аромат/линейка → бренд».
6. Использует статистические ассоциации и доверенный справочник, полученные из исторических данных.
7. Находит прямые конфликты брендов и применяет нечёткое сравнение через `RapidFuzz`.
8. Возвращает технический статус и пояснение.

| Статус | Значение |
|---|---|
| `MATCH` | Соответствие подтверждено правилами |
| `LIKELY_MATCH` | Вероятное соответствие; менее уверенный результат |
| `MISMATCH` | Найдены признаки противоречия |
| `REVIEW` | Недостаточно оснований для автоматического решения; ручная проверка |

Статусы **не являются юридическим заключением о регистрации товарного знака**. Правила оценивают согласованность полей записи.

## Полный прогон

Откройте `full_dataset_analysis_ru.ipynb` и выполните ячейки по порядку. Он рассчитывает справочники, проводит speed-test, затем вызывает `check_trademark` для каждой записи, выводит статистику по статусам/причинам и сохраняет файл:

`perfumery_brands_checked_full.csv`

Этот CSV может быть большим; **не коммитьте его**. Не добавляйте также `.ipynb_checkpoints/` и локальные датасеты.

Для локальных быстрых проверок используйте небольшую выборку вместо полного прогона; остальные ноутбуки включают демонстрационные проверки на 5000 строках.

## Историческая ручная оценка baseline

Отдельно в процессе разработки была вручную размечена выборка из 100 товаров: 68 `MATCH`, 19 `MISMATCH`, 13 `UNCERTAIN`. Основные метрики рассчитаны по 87 однозначным записям (13 `UNCERTAIN` исключены), считая `LIKELY_MATCH` направленным `MATCH`, а `REVIEW` — отказом от автоматического решения.

| Показатель | Результат |
|---|---:|
| Coverage — покрытие автоматическими решениями | 62,07% |
| Accuracy среди автоматических решений | 98,15% |
| Precision `MATCH` | 100% |
| Recall `MATCH` | 73,53% |
| F1 `MATCH` | 84,75% |
| Precision `MISMATCH` | 75% |
| Recall `MISMATCH` | 15,79% |
| F1 `MISMATCH` | 26,09% |

**Ограничения оценки:** статистические справочники текущего исследовательского прототипа строились из общего CSV до строгого `train/test split`, поэтому показатели следует рассматривать как предварительную оценку baseline, а не независимое production-качество. Полный автоматический прогон **не** является заменой ручной разметке и валидации.

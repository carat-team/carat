# Проверка соответствия наименования типу парфюмерии

Проект проверяет, соответствует ли явное обозначение типа парфюмерии в названии товара значению атрибута «Тип парфюмерии».

## Возможные статусы

- `ok` — тип в названии совпадает с атрибутом.
- `warning` — обнаружено явное несоответствие.
- `manual_review` — тип неизвестен или название неоднозначно; нужна ручная проверка.
- `not_checked` — недостаточно данных или в названии нет явного маркера типа.

`not_checked` не означает, что карточка корректна. Алгоритм намеренно не делает вывод без достаточных оснований.

## Запуск 100 автоматических тестов

Требуется Python 3.10+; для тестов сторонние библиотеки не нужны.

```bash
python -m unittest -v test_perfumery_name_check.py
```

Тесты проверяют матрицу типов, граничные случаи, синонимы, неоднозначные значения и подсчёт метрик. Успешный запуск должен завершиться сообщением `Ran 100 tests` и `OK`.

## Построение метрик для 100 тестовых карточек

```bash
python main.py
```

Команда создаёт в текущей папке:

- `metrics_dashboard.png` — график с распределением статусов и ключевыми метриками;
- `metrics_report.json` — полный отчёт с метриками и результатом по каждой карточке.

Для изображения установите Matplotlib:

```bash
python -m pip install matplotlib
```

Сам алгоритм и 100 unit-тестов не требуют Matplotlib.

## Какие метрики считаются

- общее количество карточек;
- количество `ok`, `warning`, `manual_review` и `not_checked`;
- доля предупреждений от общего количества;
- покрытие автоматической проверкой (`ok` + `warning`);
- время пакетной обработки и карточек в секунду;
- распределение срабатываний по идентификаторам правил.

Показатели из `main.py` рассчитаны на демонстрационном синтетическом наборе из 100 карточек. Они не являются оценкой качества на реальном каталоге. Для расчёта precision/recall/F1 нужна отдельная размеченная выборка с эталонными ответами.

## Метрики качества (precision / recall / F1)

```bash
python evaluation.py              # использует gold_labeled.csv
python evaluation.py my_gold.csv  # или свою размеченную выборку
```

CSV: `name`, `declared_type`, `expected_status` (ответ эксперта: `ok` / `warning` / `manual_review` / `not_checked`).
Считаются accuracy, macro-F1, precision/recall/F1 по каждому статусу и матрица ошибок; отчёт сохраняется в `quality_report.json`.
`gold_labeled.csv` — стартовая разметка для примера; для оценки реального каталога замените её выборкой из настоящих карточек.

Дополнительные тесты (26 шт.):

```bash
python -m unittest -v test_metrics_and_quality.py
python -m unittest discover -v          # все 126 тестов
```

Три теста помечены `expectedFailure` — это найденные недочёты алгоритма (см. `KnownIssuesTests`).

## Правила сравнения (уточнения)

- Если в названии несколько разных типов: `ok`, когда атрибут совпадает с первым из них или это ДУХИ, а слово «духи» стоит в названии позже («Eau de Parfum … духи 15мл»; `_ACCEPTED_ANYWHERE`); иначе `manual_review` (правило `PERFUMERY_TYPE_AMBIGUOUS`).
- Если в атрибуте несколько типов («EDT; ДУХИ»): `manual_review` (`PERFUMERY_TYPE_MULTIPLE_DECLARED`).
- «Твёрдые духи» в названии при типе ДУХИ считаются совпадением (`_COMPATIBLE_TYPES` в `perfumery_name_check.py`, чтобы отключить — оставьте множество пустым).
- «Parfum de Toilette» распознаётся как туалетная вода.

## Использование в коде

```python
from perfumery_name_check import check_perfumery_name, check_products_with_metrics

result = check_perfumery_name("Туалетная вода Rose 50 мл", "ДУХИ")
print(result["status"])  # warning

report = check_products_with_metrics([
    {"name": "Духи Rose 50 мл", "declared_type": "ДУХИ"},
    {"name": "Туалетная вода Rose 50 мл", "declared_type": "ДУХИ"},
])
print(report["metrics"])
```
